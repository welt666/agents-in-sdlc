使用 GitHub Copilot 智能体模式时，它会自主探索代码库、提出更改、编辑文件并运行命令。由于这些工作会在你的计算机上实时进行，VS Code 中的 Copilot Chat 会持续显示每次工具调用和文件编辑。你可以直接在编辑器中检查每个差异、接受或拒绝单项更改，并通过后续提示引导对话、完善或扩展工作。

本练习将：

- 实时监控无障碍智能体的工作。
- 审查并接受它提出的文件编辑。
- 在会话进行中引导智能体，除了高对比度模式外还添加浅色模式切换。

## 场景

你在[练习 4][previous-lesson]中使用的无障碍自定义智能体正在实现高对比度模式。工作进行期间，设计团队提出了额外需求：为觉得默认主题太暗的用户添加浅色模式切换。你不必从头开始新对话，而是可以引导当前会话扩展工作范围。

## 监控 Copilot 的进度

Copilot Chat 视图会显示智能体执行的每个步骤，包括探索的文件、运行的命令和提出的编辑。每个文件编辑都会以内嵌差异和 **Keep** / **Undo** 控件显示。

1. 返回练习 4 中使用的 Copilot Chat 视图。
2. 智能体工作时，滚动聊天内容查看每次工具调用。你会看到文件读取、文件编辑以及它请求运行的终端命令。
3. 智能体提出文件编辑时，差异会以内嵌形式显示：
   - 选择 **Keep** 接受更改。
   - 选择 **Undo** 撤销更改，让智能体重新尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看智能体在本次会话中修改的完整文件集。

> [!NOTE]
> 如果工具调用请求权限（例如运行终端命令），智能体会暂停并显示 **Allow** 提示。只批准你认可的命令。

5. 等待智能体完成高对比度模式。完成后应会显示更改摘要。

## 引导智能体添加浅色模式

高对比度模式已实现，现在在同一对话中添加浅色模式切换。由于继续使用同一聊天会话，智能体仍保留先前工作的上下文，包括已修改的组件、样式方法和本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

    ```plaintext
    做得不错！现在再添加一个浅色模式切换，与高对比度切换并列。浅色模式应采用相同模式：通过本地存储保留设置，并且能在 UI 的同一区域访问。用户应能分别启用高对比度和浅色模式。
    ```

2. 智能体会继续工作，探索已做的更改并提出浅色模式相关修改。
3. 像审查高对比度模式一样，逐项检查新更改，并使用 **Keep** 或 **Undo**。
4. 如果智能体的实现方向不符合预期，例如试图以你不喜欢的方式重构切换 UI，可以选择聊天输入框旁的 **Stop** 按钮停止工作，再发送澄清提示。

> [!TIP]
> 引导正在进行的会话比从头开始更快。可以通过后续提示要求调整（“简化 CSS，使用 CSS 变量而不是重复选择器”）、纠正方向（“不要添加第三个开关，将浅色模式集成到现有设置面板”）或扩展范围（“还为两个开关添加键盘快捷键”）。

## 审查工作集

提交工作前，快速检查智能体修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 审查更改文件的完整列表。应能看到 Astro 组件、样式和相关测试的更新。
3. 打开几个已更改的文件并查看差异。确认其中体现了自定义智能体提供的无障碍模式，包括 ARIA 属性、键盘导航、语义化 HTML 和本地存储持久化。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课会发布这些更改。

## 总结和后续步骤

你使用 Copilot Chat 智能体模式监控并引导正在进行的会话：检查每项文件编辑、接受或拒绝更改，并在保留上下文的同时通过后续提示扩展工作。

本课中，你了解了：

- 实时监控智能体工作。
- 接受和拒绝单项文件编辑。
- 使用后续提示在会话进行中引导智能体。

在[下一课][next-lesson]中，你将把无障碍工作发布为拉取请求，并审查本实验中本地自定义智能体生成的更改。
