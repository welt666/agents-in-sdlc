我们先为项目添加了一项小功能，但更大的更改需要更完善的流程。GitHub Copilot app 可以配合组织现有的工作流，帮助我们用正确的方法构建正确的内容。从本课开始，你将通过几节课程遵循典型的智能体驱动开发流程：从议题出发生成新功能，确认代码有效、功能符合预期，最终成功合并到项目中。

> [!NOTE]
> 在整个功能工作流中，你会继续使用同一会话。通常，不同文件类型的工作会放在不同会话或 PR 中，但为了让你聚焦核心概念，本研讨会会采用简化做法。

本课将：

- 根据 GitHub 议题开始新的智能体会话。
- 在 **Plan** 模式下定义需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器画布中手动验证功能。

继续处理此功能时，你还将更新存储库说明、自定义现有的 `quality-checks` 技能、添加 MCP 验证、创建 QA 智能体，并创建功能 PR。

## 场景

Tailspin Toys 的目录不断扩大，访问者需要按类别和发行商筛选游戏。待办事项中的议题描述了该功能，但组合类别等细节需要在编写代码前达成一致。你将使用 Plan 模式确定这些决策，然后授权 Autopilot 在明确范围内实现功能。

## 背景

在开发流程中引入 AI 编码智能体并不会改变基本原则。事实上，这些原则变得更加重要！大多数开发人员遵循类似的流程：

1. 打开已提交的议题，查看要完成的工作详情。
2. 制定构建方案。
3. 编写并审查代码。
4. 运行测试以验证代码。
5. 手动验证新功能。
6. 创建拉取请求 (PR)。
7. 代码通过审查且持续集成流程成功后，合并代码。

> [!NOTE]
> 具体流程会因团队和组织而异，但大多数流程都与上述方式类似。

遵循这种标准做法，可以确保 AI 生成的代码符合既定要求，并经过与手写代码相同的审查流程。

## 会话模式

**会话模式**决定智能体可以自主行动到什么程度。可以通过提示框下方的下拉列表设置模式，并随时更改：

- **Interactive**：你与智能体协作。智能体提出更改建议，并等待你的输入后再继续。
- **Plan**：智能体先制定计划。你审查并批准计划后，智能体才会执行。
- **Autopilot**：智能体完全自主工作，包括编写代码、运行测试和迭代，无需等待输入。

先在 Plan 模式中审查计划，再使用 Autopilot 实现。

## 从议题启动会话

开始前，确认星级评分 PR 已合并，并且本地 `main` 已更新。

1. 在侧边栏 **Sessions** 下，选择 Tailspin Toys 存储库文件夹，然后在存储库顶部导航中选择 **Issues**。打开 **Allow users to filter games by category and publisher**。这是已预置的议题，无需再创建。
2. 选择 **New session**，并选择基于更新后 `main` 的 **new working tree**。

    ![GitHub Copilot app 的议题视图，箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认议题已附加到会话，并在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，请让智能体运行 `node --version` 和 `npm --version`。如果命令在终端中有效，但在会话中无效，请检查应用的 PATH 或版本管理器设置，然后完全退出并重新打开应用。重新尝试失败的操作和检查；不要仅因为智能体找不到 npm 就重新安装 npm。

## 规划筛选功能

规划能让你在 Copilot 编写代码前审查实现方案。由于会话从议题启动，Copilot 已获得功能请求的上下文。发送：

```plaintext
实现此功能。
```

回答 Copilot 的问题，并根据议题的验收标准审查计划。确认计划涵盖类别和发行商筛选、无障碍控件、数据访问更改和测试。讨论尚不明确的行为，例如多个类别如何组合，或没有游戏匹配时该如何处理。

计划应使用项目现有工具运行 lint、单元测试、E2E 测试和类型检查。将计划范围聚焦在筛选功能的实现和测试；完成质量工作流后再创建 PR。批准计划前，请求所需修改，并保留议题 URL 及达成一致的说明，以便之后验证。

## 明确批准 Autopilot

对计划满意后，选择 **Approve and implement this plan**，或当前版本中名称相近的选项。确认当前模式，不要假定批准计划会自动切换模式。确认模式指示器显示 **Autopilot**。

Copilot 将开始实现功能！你会看到它按照既定计划逐步工作、生成代码并运行测试。

> [!NOTE]
> 批准后可能立即开始实现，因此请先审查计划。如果 Copilot 报告缺少依赖项或端口冲突，请先解决设置问题，再将检查视为已完成。只停止自己启动的服务器。

## 审查并验证实现

代码生成后，和其他代码一样，合并前也需要审查。现在检查代码并运行网站，确认一切正常。

1. 打开 **Changes**，检查筛选功能实现和测试。
2. 将结果与议题和已批准的说明进行比较，包括多类别和发行商组合。确认更改符合存储库现有说明。
3. 检查 lint、单元测试、E2E 测试和类型检查的输出。跳过的检查不能算通过。
4. 接受实现前，解决失败项并重新运行受影响的检查。Playwright 的 E2E 配置会构建并提供预览服务，也可能复用本地服务器；确认被测服务器属于此工作树，而不是之前课程启动的服务器。

## 探索新功能

代码看起来没有问题，但能否正常运行？像之前一样启动应用，并在浏览器画布中打开网站。

1. 使用以下提示，请 Copilot 启动应用并在浏览器画布中打开页面：

    ```plaintext
    启动应用并在浏览器画布中打开。
    ```

2. 稍等片刻，应用将启动，Copilot app 内会打开浏览器窗口。
3. 选择一个类别，确认结果与该类别匹配。清除筛选，再选择一个发行商，确认结果与该发行商匹配。
4. 同时应用类别和发行商筛选，并对照议题和已批准的计划检查结果。如果支持多个类别，还要验证已商定的组合行为。
5. 尝试一个没有匹配游戏的筛选组合并检查空状态。清除或重置筛选，确认完整列表恢复。
6. 完成后，使用以下提示要求 Copilot 停止本会话启动的开发服务器并关闭浏览器画布：

    ```plaintext
    停止开发服务器并关闭浏览器画布。
    ```

## 为后续课程保留此会话

暂时不要创建或合并筛选功能 PR。请保留此会话、工作树和分支，供第 4 至第 8 课继续使用。接下来会将自定义说明应用到筛选代码，然后添加技能和 QA 改进，最后在第 8 课创建并合并合并后的 PR。停止开发服务器后，可以将会话留在空闲状态；下一课再返回同一会话。

你使用不同的智能体模式构建并审查了一项功能。本课中，你：

- 根据 GitHub 议题开始了新的智能体会话。
- 在 **Plan** 模式下定义了需求。
- 使用 **Autopilot** 模式实现了新功能。
- 审查了代码。
- 在浏览器画布中手动验证了功能。
