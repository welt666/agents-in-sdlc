GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行します。VS Code の Copilot Chat はローカル環境でリアルタイムに作業するため、すべてのツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を適用または取り消し、エディターを離れずに追加のプロンプトを送信して作業を調整できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして適用します。
- セッション中にエージェントを調整し、ハイコントラストモードに加えてライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティのカスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいとのことです。新しい会話を始める代わりに、現在のセッションを調整して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各手順が表示されます。調査したファイル、実行したコマンド、提案された編集内容を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - 変更を適用するには **Keep** を選択します。
    - 変更を取り消して再度作業させるには **Undo** を選択します。
4. チャットの上部にある **Files changed** の表示を開くと、このセッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ターミナルコマンドの実行など、ツールの使用許可を求める場合があります。その場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。最後に、変更内容の概要が表示されます。

## ライトモードを追加するようにエージェントを調整する

ハイコントラストモードを実装したら、同じ会話でライトモードの切り替えも依頼します。会話を継続するため、エージェントはコンポーネント、スタイルの方針、設定をローカルストレージに保存する方法など、前の作業のコンテキストを保持しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前の作業を確認し、ライトモードのための変更を提案します。
3. ハイコントラストモードと同様に、新しい編集内容を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合（たとえば、好みでない方法で切り替え UI を再構成しようとした場合）は、チャット入力欄の横にある **Stop** ボタンで停止して、説明を追加します。

> [!TIP]
> 進行中のセッションを調整すると、新しい会話を始めるよりも速く作業できます。追加のプロンプトを使って、変更を依頼（「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使用する」）、方向を修正（「3 つ目の切り替えを追加せず、ライトモードを既存の設定パネルに追加する」）、または範囲を拡張（「両方の切り替えにキーボードショートカットも追加する」）できます。

## 作業ファイルをレビューする

変更をコミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージへの保存など、カスタムエージェントが示したアクセシビリティのパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、各ファイル編集を確認し、個々の変更を適用または取り消し、コンテキストを失わずに追加のプロンプトを送って作業を拡張しました。

この演習では、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する
- 個々の編集を適用または取り消す
- 追加のプロンプトを使ってセッションを途中で調整する
