フィルター機能の実装、指示とスキルの更新、品質保証 (QA) プロファイル、テストが、1 つのブランチに保存されています。これらをまとめてレビューし、プルリクエストを作成しましょう。星評価のプルリクエスト (PR) は自分でマージしました。今回は **Agent Merge** に PR の管理を任せます。

> [!NOTE]
> 通常は機能、指示の更新、スキルの更新、QA エージェントを複数の PR に分けます。このワークショップでは手順を簡潔にするため、フィルター機能と品質ワークフロー全体を同じセッションとブランチで進め、1 つの PR にまとめました。

このレッスンでは、次のことを行います。

- Agent Merge と、マージのライフサイクルを自動化する方法を学びます。
- 機能の PR 全体と検証結果を確認します。
- レビューの後に Agent Merge を許可し、PR がマージされたことを確認します。

## シナリオ

フィルター機能のワークフローを通じて、Copilot を使って機能を計画、実装、検証しました。Tailspin Toys は、マージの承認を開発者が管理しながら、残りの PR 作業を自動化したいと考えています。

## Agent Merge とは

**Agent Merge** は、GitHub Copilot app でプルリクエストをマージするために必要な残りの作業を自動化します。有効にすると、アプリのセッションはプルリクエストを読み取り、CI チェックの失敗を修正したり、レビューコメントに対応したり、必要に応じてリベースしたりして、PR をブロックしている問題に取り組みます。GitHub が許可するとマージします。バックグラウンドで実行され、アプリを再起動しても継続し、プルリクエストがマージされると自動的に停止します。

これまでは自分で **Merge pull request** を選択していました。Agent Merge に作業を任せることもできますが、コードの編集やマージには引き続き明示的な承認が必要です。マージ権限を与える前に、許可される操作と作業内容をレビューしてください。

## Agent Merge で PR を管理する

コードの作成とレビューが完了したら、Agent Merge に PR のプロセスを管理させましょう。

1. エージェントピッカーで **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択してプロセスを開始します。ドロップダウンから選ぶだけでは開始されません。

Agent Merge のプロセスが始まります。次の作業を行います。

- タイトルと説明を含むプルリクエストを作成します。
- issue からセッションを開始した場合は、説明の本文で関連する issue を参照します。
- ターゲットブランチへのリベースを行うか、マージ競合に対処します。
- CI を監視し、すべてのチェックに合格することを確認します。
- PR を監視し、ほかの開発者や Copilot code review からのフィードバックに対応します。
- 必要に応じて、すべてのチェックに合格した後、PR を自動的にマージします。

すべてのチェックに合格した後、Agent Merge に PR もマージさせます。

5. マージを許可する前に、PR の差分と検証結果をレビューします。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** の横にチェックが付いていることを確認します。
8. エージェントに明示的にマージを依頼します。

    ```plaintext
    Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
    ```

9. 進捗を確認し、報告されたブロッカーに対処します。続行する前に PR の状態が **Merged** になっていることを確認してください。マージ権限を有効にしたことや、エージェントが実行中であることは、マージ完了の確認にはなりません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護や権限不足を回避しません。続行する前に、そのようなブロッカーを解消してください。
